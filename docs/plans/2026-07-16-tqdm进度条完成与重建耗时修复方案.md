# tqdm进度条完成与重建耗时修复方案

## 背景

当前 case 进度条在完成或可见窗口上移重建后，tqdm 新对象会把内部计时重置为当前时刻，并且 `initial` 等于当前 step 数。这样默认右侧信息会显示为 `00:00<?, ?step/s`，即使自定义 postfix 中的 `elapsed` 已经是正确的累计耗时。

## 修改方案

- 在 `TqdmCaseProgressManager` 内部为 tqdm progress bar 增加计时恢复逻辑。
- 每次刷新、推进、完成 progress bar 前，将 tqdm 的 `start_t` 回拨到 `当前tqdm时间 - state.elapsed_seconds`。
- 将 tqdm 的 `initial` 统一恢复为 `0`，避免重建后 `n - initial == 0` 导致速率和剩余时间不可计算。
- 保持现有 postfix 字段不变，避免影响已有终端展示格式。
- 补充回归测试，覆盖完成态和可见窗口上移导致的重建态。

## 验证方式

- 运行新增进度条测试，确认完成态显示 `消耗总时间<00:00`。
- 运行新增进度条测试，确认窗口上移重建后的活动进度条显示真实累计耗时。
- 清理测试产生的 `__pycache__` 与 `.pytest_cache` 缓存。

## 附录A. 项目中没有把握实现的模块部分

当前修复仅涉及 `dynsteer.progress.TqdmCaseProgressManager` 的 tqdm 内部显示状态恢复，不改 evaluator、benchmark 适配或调度流程；暂无没有把握实现的模块部分。
