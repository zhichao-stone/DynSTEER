# tqdm进度条完成态不重建修复方案

## 背景

当前 case 完成时会把 `bar.total` 收敛为真实 step 数，但随后会重建所有可见 tqdm bar。重建后的已完成 bar 从 `initial == total` 开始，tqdm 无法保留旧对象的 elapsed 与 rate 统计，因此终端显示为 `00:00<?, ?step/s`。

## 修改方案

- 为进度管理器增加增量同步可见 bar 的内部逻辑。
- `case_finished` 完成时只更新当前 bar 的 `total`、postfix 与刷新状态；可见窗口顺序没有变化时不重建已有 bar。
- `case_started` 新增可见 case 时只创建缺失 bar；只有可见窗口发生裁剪或位置需要重排时才重建。
- 补充回归测试，验证已完成 bar 在完成和后续 case 启动时保持同一个对象。

## 验证方式

- 先运行新增测试，确认当前实现失败。
- 修改实现后运行进度条相关测试。
- 清理测试产生的 `__pycache__` 与 `.pytest_cache` 缓存。

## 附录A. 项目中没有把握实现的模块部分

当前修复只涉及 `dynsteer.progress.TqdmCaseProgressManager` 的内部可见窗口同步逻辑，不涉及外部 benchmark/evaluator 流程；暂无没有把握实现的模块部分。
