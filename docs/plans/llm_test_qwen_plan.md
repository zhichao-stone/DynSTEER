# LLM 双模型单次响应时间测试修改计划

## 1. 目标

扩展主目录下的 `llm_test.py`，在现有 `deepseek-v4-flash` 单次请求测试之外，增加 `qwen-plus-2025-12-01` 的单次请求测试。

## 2. 修改内容

- 分别从以下配置读取模型凭据，禁止硬编码敏感信息：
  - DeepSeek：`data/experiments/toolsandbox_main_3.json`
  - Qwen：`data/experiments/toolsandbox_main_2.json`
- 抽取单个模型的请求与结果输出逻辑，两个模型使用相同提示词、超时时间、重试策略和完整响应计时口径。
- 在主流程中显式执行两次测试，不在循环中发起网络请求。
- 单个模型失败时输出明确错误，并继续测试另一个模型；任一测试失败后脚本返回非零退出码。

## 3. 验收方式

- 执行 Python 语法检查。
- 在不发起外部 API 请求的情况下验证两份配置均能读取对应模型、API Key 与 Base URL。
- 不主动执行真实模型请求，避免未经要求消耗 API 配额。

## 4. 约束检查

- 不输出或复制 API Key。
- 每个模型禁用 SDK 自动重试，确保单次测试最多发起一次 HTTP 请求。
- 不修改现有业务模块或引入新依赖。

## 附录A. 项目中没有把握实现的模块部分

无代码实现不确定项。实际响应时间受网络、服务负载、API 凭据状态和模型可用性影响，需要运行脚本后确认。
