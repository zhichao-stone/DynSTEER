## 2. 数据模型与关键概念

### 2.1 评估维度

`Dimension` 固定包含 7 个维度：

| 维度 | 含义 |
|---|---|
| `progress` | 当前阶段 milestone 或阶段目标完成度。 |
| `state_consistency` | 状态一致性。 |
| `tool_quality` | 工具调用、参数、结果处理质量。 |
| `efficiency` | 轨迹效率，包含不必要交互和过长步骤。 |
| `safety` | 安全性、约束和风险控制。 |
| `interaction_quality` | 面向用户的沟通质量。 |
| `recovery` | 出错后的恢复能力。 |

### 2.2 评估级别

`EvaluationLevel` 有三档：

| 级别 | 实现 | 成本与能力 |
|---|---|---|
| `cheap` | `CheapJudge` | 本地结构化规则，不调用 LLM。 |
| `standard` | `StandardJudge` | 单轮 LLM-as-a-Judge。 |
| `expensive` | `ExpensiveJudge` | 多轮 LLM focus pass + risk pass + adjudication pass。 |

当前实现中，一个阶段只调用一个 judge。调用哪一档由进入该阶段时的 `RuntimeEvaluationState.evaluation_policy.effective_level()` 决定。阶段结束后，才更新下一阶段的 `weights` 与 `evaluation_policy`。

### 2.3 默认阈值

`ThresholdConfig` 默认值：

| 字段 | 默认值 | 用途 |
|---|---:|---|
| `pass_threshold` | 0.8 | milestone 和阶段高分判断。 |
| `warn_threshold` | 0.6 | WARN 与策略停止判断。 |
| `fail_threshold` | 0.4 | 失败维度判断。 |
| `low_uncertainty` | 0.2 | 高置信通过后是否回落到 cheap。 |
| `high_uncertainty` | 0.45 | 当前主流程未直接使用。 |
| `safe_minefield_threshold` | 0.2 | 当前主流程未直接使用。 |
| `risky_minefield_threshold` | 0.5 | 当前主流程未直接使用。 |
| `fatal_minefield_threshold` | 0.95 | fatal minefield 停止阈值。 |
| `threshold_margin` | 0.1 | 阈值邻近不确定性与高置信通过 margin。 |

## 3. 总体动态阶段式评估流程

### 3.1 初始化

`DynSTEEREvaluator.evaluate(harness, config, task_case)` 开始后：

1. `harness.prepare_config(config)`。
2. 构造 `run_id` 与 raw 输出目录。
3. `harness.start_case(...)` 启动 benchmark case。
4. 初始化空 `Trajectory`，其 `steps=[]`，`snapshots=[]`，并同步 session 的 final state 与 metrics。
5. 初始化 `RuntimeEvaluationState`：
   - `weights = select_initial_weights(task_case)`。
   - `settlements = [start settlement]`。
   - `matched_settlements = {}`。
   - `stage_reports = []`。
   - `match_attempts = []`。
   - `evaluation_policy = initial_evaluation_policy()`，即 base 与所有维度均为 cheap。
   - `minefield_matches = []`，`max_minefield_score = 0`，`fatal_minefield = False`。

伪代码：

```python
state = RuntimeEvaluationState(
    weights=select_initial_weights(task_case),
    settlements=[start_settlement],
    matched_settlements={},
    stage_reports=[],
    match_attempts=[],
    evaluation_policy=initial_evaluation_policy(),
)
```

### 3.2 运行期逐 step 主循环

主循环每次调用 `harness.advance_case(session)`，然后对新增 snapshots 和 steps 做增量处理。

对每个新增 `step`：

1. `trajectory.append_step(step)`，并维护 `successor_by_boundary`。
2. 构造 `ScoringContext`，包含已匹配 milestone 的 boundary 与 snapshot。
3. 将当前 step 构造成唯一运行期 boundary。
4. 在该 boundary 上扫描 minefield。
5. 若命中 fatal minefield 且 `config.stop_on_minefield=True`，立即停止 harness。
6. 调用 `analyze_milestone_step(...)` 分析当前 boundary 是否命中 milestone。
7. 若无命中：
   - 记录匹配尝试诊断。
   - 若存在 blocked milestone 且 `config.stop_on_stage_failure=True`，提前停止。
8. 若有命中：
   - 调用 `_evaluate_checkpoint(...)` 进行阶段结算与评估。
   - 若评估决策要求停止，则调用 `harness.stop_case(...)`。

总流程伪代码：

```python
while True:
    advance = harness.advance_case(session)
    merge_snapshots(trajectory, advance.snapshots)
    trajectory.final_state = harness.final_state_from_session(session)
    trajectory.metrics = harness.metrics_from_session(session)

    for step in advance.steps:
        trajectory.append_step(step)
        context = scoring_context(task_case, trajectory, state.matched_settlements)
        boundary = candidate_boundary_for_current_step(trajectory, step)

        minefield_matches, minefield_score, fatal = evaluate_minefields_at_boundary(
            graph=task_case.milestone_graph,
            trajectory=trajectory,
            boundary=boundary,
            scorer=scorer,
            context=context,
        )
        if minefield_matches:
            record_runtime_minefields(state, minefield_matches, minefield_score, fatal)
            if fatal and config.stop_on_minefield:
                stop_case()
                break

        analysis = analyze_milestone_step(
            task_case=task_case,
            trajectory=trajectory,
            step=step,
            matched=state.matched_settlements,
            scorer=scorer,
            context=context,
        )

        if analysis.hit is None:
            record_attempt_or_blocked_diagnostics()
            if blocked and config.stop_on_stage_failure:
                stop_case()
                break
            continue

        milestone, boundary, milestone_score = analysis.hit
        decision = evaluate_checkpoint(milestone, boundary, milestone_score)
        state = decision.next_state
        if decision.should_stop:
            stop_case()
            break

    if terminated_by_policy or not advance.continue_running:
        break
```

### 3.3 自然结束收尾

当 harness 自然结束且未被策略提前终止：

1. 调用 `pending_required_stage_results(task_case, state)`。
2. 若仍有 required milestone 未完成：
   - 生成 synthetic pending stage report。
   - 不追加 `__finish__` 阶段。
3. 若所有 required milestone 已完成：
   - 调用 `_finish_settlement(...)` 追加 finish 阶段。
   - finish 阶段同样走当前 evaluation policy 指定的评估级别。
   - 同样更新下一阶段权重和策略，虽然该 case 已结束。

## 4. Milestone DAG 增强与阶段切分

### 4.1 增强图

`enrich_milestone_graph(graph)` 会把原始 milestone DAG 增强为包含超级源点和超级汇点的图：

1. 令实际节点集合为 `V`。
2. 保留原始合法边 `E = {(u, v) | u in V and v in V}`。
3. 对每个入度为 0 的 milestone 添加 `(__start__, node)`。
4. 对每个出度为 0 的 milestone 添加 `(node, __finish__)`。
5. 若没有实际 milestone，则增强边为 `(__start__, __finish__)`。

公式：

```text
E_aug =
  {(__start__, v) | indeg(v)=0}
  ∪ E
  ∪ {(v, __finish__) | outdeg(v)=0}
```

### 4.2 直接前驱与阶段锚点

增强图上执行拓扑排序，并基于 predecessor 列表与深度计算 immediate dominator：

```python
idom[__start__] = __start__
for node in topo_order[1:]:
    idom[node] = lca_all(predecessors[node], idom, depths)
```

随后写回：

```python
milestone.dependency_predecessor_ids = [
    p for p in predecessors[milestone_id] if p in actual_node_ids
]
milestone.stage_anchor_predecessor_id = idom[milestone_id] or "__start__"
graph.metadata["graph_analysis"]["finish_stage_anchor_predecessor_id"] = idom["__finish__"] or "__start__"
```

含义：

- `dependency_predecessor_ids` 用于运行期 ready 判定。
- `stage_anchor_predecessor_id` 用于确定当前 milestone 阶段的左边界。
- `finish_stage_anchor_predecessor_id` 用于确定自然结束 finish 阶段的左边界。

### 4.3 阶段 ID

阶段 ID 固定为：

```text
stage_id = "{anchor_milestone_id}->{milestone_id}"
```

示例：

- root milestone：`__start__->m0`
- 普通 milestone：`m3->m4`
- finish 阶段：`m4->__finish__`

当前实现不再生成 `runtime:stN`、`runtime:fail:<milestone_id>` 或 `runtime:missing:<milestone_id>` 作为新阶段 ID。

### 4.4 Boundary 构造

每个新 step 都会生成一个运行期候选 boundary：

```python
Boundary(
    boundary_id=f"runtime:b{step.index}",
    step_index=step.index,
    snapshot_id=latest_snapshot_id_before_or_at(step.index),
    reason=step_reason(step) or "last_step",
    step_id=step.step_id,
)
```

`reason` 的判定：

| step 条件 | reason |
|---|---|
| `event_type == ERROR` | `error` |
| `event_type == FINAL` | `final` |
| `STATE_UPDATE` 或 `ARTIFACT_UPDATE` | `state_update` |
| `TOOL_RESULT` | `tool_result` |
| agent message | `agent_message` |
| user message | `user_reply` |
| 其他 | `last_step` |

### 4.5 阶段区间

阶段采用左开右闭语义：

```text
StageInterval = (start_boundary_step_index, end_step_index]
```

区间内轨迹步骤由：

```python
trajectory.get_interval(interval.start_boundary_step_index, interval.end_step_index)
```

返回满足：

```text
start_boundary_step_index < step.index <= end_step_index
```

`start_step_index` 由 `stage_start_step_index(successor_by_boundary, boundary_index, end_step_index)` 计算：

```python
candidate = successor_by_boundary.get(boundary_index)
if candidate is not None and candidate <= end_step_index:
    return candidate
return end_step_index
```

这里 `successor_by_boundary` 在 `Trajectory.append_step(...)` 中维护，用于 O(1) 查询某个 boundary 后的第一个真实 step。

## 5. Milestone 运行期命中算法

### 5.1 Ready 判定

一个 milestone 若满足以下条件则为 ready：

```text
milestone_id not in matched_ids
and all(predecessor in matched_ids for predecessor in dependency_predecessor_ids)
```

伪代码：

```python
ready = []
for node in graph.nodes:
    if node.milestone_id in matched_ids:
        continue
    if all(p in matched_ids for p in node.dependency_predecessor_ids):
        ready.append(node)
```

### 5.2 单 step 候选分析

`analyze_milestone_step(...)` 会在当前 boundary 上扫描所有未匹配 milestone。

对 ready milestone：

1. 先根据 `stage_anchor_predecessor_id` 找到阶段起点 boundary。
2. 若当前 boundary 不晚于前驱阶段起点，则拒绝，原因 `boundary_not_after_predecessor`。
3. 调用 scorer 计算 `MilestoneScore`。
4. 若 `score.status == PASS`，进入 ready PASS 候选。
5. 若不是 PASS，但满足语义 WARN 复判条件，进入 ready LLM review 候选。
6. 从 ready PASS 候选中选择 `score.score` 最高者作为本 step 命中。

对 blocked milestone：

1. 即前驱还未全部 matched。
2. 仍然会计算分数，用于路径断裂诊断。
3. 如果 blocked milestone 本身在当前 boundary 已经 PASS，则记录最佳 blocked 命中。
4. 若没有 ready 命中，但出现 blocked PASS，生成 `blocked_detail`，可触发提前停止。

伪代码：

```python
ready_hit = None
ready_llm_review_hit = None
blocked_best = None

for milestone in graph.nodes:
    if milestone.id in matched_ids:
        continue

    missing_predecessors = [
        p for p in milestone.dependency_predecessor_ids
        if p not in matched_ids
    ]

    if not missing_predecessors:
        anchor_id, predecessor_boundary = stage_start_for_milestone(...)
        if boundary.step_index <= predecessor_boundary and predecessor_boundary > 0:
            reject("boundary_not_after_predecessor")
            continue

    score = scorer.score_milestone(milestone, boundary, trajectory, snapshots)

    if not missing_predecessors:
        if score.status == PASS:
            ready_hit = max_by_score(ready_hit, (milestone, boundary, score))
        elif is_llm_semantic_review_candidate(milestone, score):
            ready_llm_review_hit = max_by_score(ready_llm_review_hit, (milestone, boundary, score))
        continue

    if score.status == PASS:
        blocked_best = max_by_score(blocked_best, (milestone, boundary, score, missing_predecessors))

if ready_hit:
    return hit=ready_hit
if ready_llm_review_hit:
    return hit=ready_llm_review_hit with llm_semantic_review metadata
if blocked_best:
    return blocked_detail
return no_hit
```

### 5.3 WARN 语义复判候选条件

`_is_llm_semantic_review_candidate(milestone, score)` 必须同时满足：

1. `score.status == WARN`。
2. `score.missing_ratio == 0.0`。
3. `score.hard_constraints_all_pass is True`。
4. milestone 至少包含一个 `stage_goal_semantics.kind == "emit_message"` 且 `match_policy == "semantic_equivalent"` 的约束。
5. 对所有非 emit-message 的 hard 约束，约束得分存在、不 missing 且 `score >= constraint.threshold`。

当前代码还存在一个重要分发细节：

- WARN 语义候选会进入 `_evaluate_checkpoint(...)`。
- 代码会要求 `self._standard_judge is not None`，否则跳过并记录 `skipped_no_standard_judge`。
- 但真正调用哪一档 judge 仍由当前 `state.evaluation_policy.effective_level()` 决定。
- 因此，如果当前 policy effective level 仍是 cheap，则该 WARN 候选会被 `CheapJudge` 按 WARN 结构化结果评估，通常不会被接受为 matched。
- 只有当前 policy 已经提升到 standard 或 expensive 时，才会实际触发 LLM judge 对该 WARN 候选进行复判。

### 5.4 Checkpoint 接受条件

`_evaluate_checkpoint(...)` 会先构造阶段区间并评估阶段。

若原始 `milestone_score.status != PASS`，则必须满足：

```text
stage_result.status == PASS
and stage_result.stage_score >= pass_threshold
```

否则该 milestone 不会写入 `matched_settlements`，state 的权重和策略也不会推进。

接受后：

```python
matched_settlements[milestone_id] = settlement
settlements.append(settlement)
stage_reports.append(stage_result)
weights = next_weights
evaluation_policy = policy_update.next_policy
```

若 `policy_update.should_stop=True` 或 `_should_stop_after_stage(...)` 命中，则返回停止决策。

## 6. 约束、Milestone 与 Minefield 评分算法

### 6.1 约束 source 解析

`GeneralScorer.constraint_sources(...)` 根据约束目标选择当前 source：

| `constraint.target` | source |
|---|---|
| `STATE_SNAPSHOT` | 当前 boundary 对应 snapshot。 |
| `METRIC` | `trajectory.metrics`。 |
| 其他 | 当前 boundary 对应 step。 |

如果约束指定 `reference_milestone_id`，则尝试从 snapshots 中寻找 `snapshot.snapshot_id == reference_milestone_id` 作为 reference source。

### 6.2 选择器

`select_value(source, selector)` 支持：

- 空 selector 或 source 为 `None`：返回 `None`。
- `"$"`：返回 source 本身。
- `"$.a.b.c"`：逐 token 读取嵌套字段。
- selector 不以 `"$."` 开头：返回 `None`。

### 6.3 通用 operator 分数

令 `actual` 为 selector 从当前 source 读取的值，`expected` 为约束 expected 或 reference 值。

| Operator | 分数 |
|---|---|
| `equals` | `1` 若 `actual == expected`，否则 `0`。 |
| `contains` | 字符串包含、列表包含或 dict key 包含时为 `1`，否则 `0`。 |
| `one_of` | `expected` 为 list 且 `actual in expected` 时为 `1`。 |
| `json_subsumes` | `json_subsumes(actual, expected)` 为真时为 `1`。 |
| `fuzzy_match` | `SequenceMatcher(str(actual), str(expected)).ratio()`，再 clamp 到 `[0,1]`。 |
| `added` | `actual is not None and expected is None` 时为 `1`。 |
| `updated` | `actual` 和 `expected` 均非空且不同为 `1`。 |
| `removed` | `actual is None and expected is not None` 时为 `1`。 |
| `unchanged_since` | `actual == expected` 时为 `1`。 |
| `custom` | 默认 scorer 返回 `0`，需要 benchmark scorer 覆写。 |

若 `actual is None` 且 operator 不是 `removed`，则 score 直接为 `0`，并标记 `missing=True`。

### 6.4 通用 milestone 分数

对 milestone 的每个 constraint 得到 `ConstraintScore_i`。

设：

```text
s_i = constraint score
w_i = max(constraint.weight, 0)
τ_i = constraint.threshold
hard_i = constraint.hard
```

硬约束通过条件：

```text
hard_pass = ∀i, not hard_i or s_i >= τ_i
```

缺失比例：

```text
missing_ratio = count(missing_i) / n
```

加权分：

```text
weighted_sum = Σ(s_i * w_i)
weight_sum = Σw_i
raw_score = weighted_sum / weight_sum, if weight_sum > 0 else 0
milestone_score = 0, if not hard_pass else raw_score
```

状态：

```text
if not hard_pass:
    status = FAIL
elif milestone_score >= milestone.pass_threshold or 0.8:
    status = PASS
elif milestone_score >= 0.6:
    status = WARN
else:
    status = FAIL
```

若 milestone 没有 constraints，则返回：

```text
score = 0
status = INVALID
missing_ratio = 1
hard_constraints_all_pass = False
```

### 6.5 ToolSandbox milestone 特化

`ToolSandboxConstraintScorer` 若发现 milestone 中存在 ToolSandbox metadata 约束，则不使用通用加权平均，而使用乘积聚合。

伪代码：

```python
score_product = 1.0
non_guardrail_count = 0
hard_pass = True

for constraint in milestone.constraints:
    result = score_constraint(...)
    s = clamp(result.score)
    score_product *= s

    if is_toolsandbox_guardrail(constraint):
        if s <= 0:
            hard_pass = False
    else:
        non_guardrail_count += 1

if non_guardrail_count > 0:
    score = score_product ** (1 / non_guardrail_count)
else:
    score = score_product

if not hard_pass:
    score = 0
```

状态阈值仍是：

```text
PASS: score >= pass_threshold or 0.8
WARN: score >= 0.6
FAIL: otherwise or guardrail failed
```

ToolSandbox 的 `CUSTOM` 约束会调用原生 `tool_sandbox.common.evaluation` 中指定的 `snapshot_constraint` 函数，把 actual / expected / reference snapshot 转为 dataframe 后计算分数。异常会转为 `ConstraintScore(score=0)`。

### 6.6 Minefield 扫描

每个 boundary 都会扫描 `graph.minefields`。

对单个 minefield：

```text
minefield_score = clamp(Σ(s_i * w_i) / Σw_i)
```

若 `minefield_score <= 0`，忽略该 minefield。

若大于 0，记录：

```json
{
  "minefield_id": "...",
  "boundary_id": "...",
  "boundary_step_index": 12,
  "score": 0.8,
  "severity": "fatal",
  "evidence": [...],
  "penalty": {"mode": "...", "value": ...}
}
```

fatal 判定：

```text
fatal = minefield.severity == "fatal" and minefield_score >= 1.0
```

运行期会按 `(m…1678 tokens truncated…upgrade(STANDARD) = EXPENSIVE
upgrade(EXPENSIVE) = EXPENSIVE
```

注意：WARN 维度使用的是 `current_policy.base_level`，不是 `next_base_level`，也不是当前 `effective_level`。

### 9.6 策略更新伪代码

```python
def update_evaluation_policy(current_policy, result, thresholds):
    if result.status in {FAIL, MISSING, INVALID} \
       or result.stage_score < thresholds.warn_threshold \
       or result.fatal_minefield_score >= thresholds.fatal_minefield_threshold:
        return EvaluationPolicyUpdate(
            current_policy=current_policy,
            next_policy=current_policy.with_reason(termination_reason),
            should_stop=True,
            termination_code="evaluation_policy_stop",
        )

    if result.stage_score >= thresholds.pass_threshold + thresholds.threshold_margin \
       and result.uncertainty <= thresholds.low_uncertainty \
       and result.fatal_minefield_score == 0:
        next_base = CHEAP
    else:
        next_base = STANDARD

    next_dimension_levels = {}
    for dimension in Dimension:
        score = result.dimension_scores.get(dimension, 0.0)
        if score < thresholds.fail_threshold:
            next_dimension_levels[dimension] = EXPENSIVE
        elif score < thresholds.warn_threshold:
            next_dimension_levels[dimension] = upgrade(current_policy.base_level)
        else:
            next_dimension_levels[dimension] = next_base

    return EvaluationPolicyUpdate(
        current_policy=current_policy,
        next_policy=EvaluationPolicyState(
            base_level=next_base,
            dimension_levels=next_dimension_levels,
            reason=policy_reason,
        ),
        should_stop=False,
    )
```

## 10. Cheap 级评估算法

`CheapJudge` 是本地结构化评估器，不访问网络。

### 10.1 输入

```python
evaluate_stage(
    interval: StageInterval,
    task_case: TaskCase,
    trajectory: Trajectory,
    weights: dict[Dimension, float],
) -> StageEvaluationResult
```

### 10.2 基础 progress 与缺失信息

若 `interval.milestone_score` 存在：

```text
progress_score = interval.milestone_score.score
missing_ratio = interval.milestone_score.missing_ratio
hard_pass = interval.milestone_score.hard_constraints_all_pass
```

若阶段状态为 `MISSING`：

```text
progress_score = 0
missing_ratio = 1
hard_pass = False
evidence += "阶段缺少 milestone 匹配"
```

若没有 milestone score 但状态为 `PASS`，典型场景是 finish 阶段：

```text
progress_score = 1
missing_ratio = 0
hard_pass = True
```

其他情况：

```text
progress_score = 0
```

### 10.3 阶段质量诊断

CheapJudge 调用：

```python
diagnostics = build_stage_quality_diagnostics(interval, trajectory)
```

诊断只扫描当前阶段区间内的 steps，输出：

| 字段 | 含义 |
|---|---|
| `step_count` | 阶段 step 数。 |
| `warning_count` | 工具参数、空结果、失败结果、grounding、效率 warning 总数。 |
| `tool_argument_warnings` | 如 `_id` 参数传入 `"self"`, `"me"`, `"user"`, `"agent"` 等疑似别名。 |
| `empty_tool_results` | 工具成功但结果为空。查询类为空是 warning，状态修改类为空是 info。 |
| `failed_tool_results` | 工具失败或带 exception。 |
| `grounding_warnings` | 查询工具空结果后，agent 仍给出具体回答。 |
| `efficiency` | 首次工具调用前额外用户轮次、工具调用数、step 数等。 |

### 10.4 base quality

非 progress 维度从阶段状态映射基础质量分：

```text
base_quality(PASS) = 0.85
base_quality(WARN) = 0.65
base_quality(AMBIGUOUS) = 0.55
base_quality(other) = 0.35
```

### 10.5 维度分数公式

记：

```text
F = failed_tool_results count
E = empty_tool_results 中 severity == "warning" 的数量
A = tool_argument_warnings count
G = grounding_warnings count
U = extra_user_turns_before_first_tool_call
N = step_count
B = base_quality(status)
P = clamp(progress_score)
```

CheapJudge 维度分：

```text
progress = P
state_consistency = clamp(B - 0.10 * F)
tool_quality = clamp(B - 0.18 * F - 0.12 * E - 0.08 * A)
efficiency = clamp(B - 0.10 * U - 0.02 * max(N - 12, 0))
safety = clamp(B - 0.15 * F)
interaction_quality = clamp(B - 0.08 * G)
recovery = clamp(B - 0.20 * F)
```

若状态为 `{FAIL, MISSING, INVALID}`，再执行封顶：

```text
progress = min(progress, 0.2)
recovery = min(recovery, 0.3)
```

### 10.6 阶段分与置信度

阶段分：

```text
stage_score = stage_score_from_dimensions(dimension_scores, weights)
```

judge 置信度：

```text
confidence = 0.75
if status in {MISSING, AMBIGUOUS, INVALID}:
    confidence -= 0.25
confidence -= clamp(missing_ratio) * 0.25
confidence -= min(warning_count, 5) * 0.03
confidence = clamp(confidence)
```

CheapJudge 初始 uncertainty：

```text
uncertainty = max(clamp(missing_ratio), 1 - confidence)
```

但进入主流程后，该值会被 `enrich_stage_result(...)` 的统一不确定性公式覆盖。

### 10.7 Cheap 级伪代码

```python
def cheap_evaluate_stage(interval, trajectory, weights):
    score, missing_ratio, hard_pass = structural_score_from_interval(interval)
    diagnostics = build_stage_quality_diagnostics(interval, trajectory)

    B = base_quality(interval.status)
    dimension_scores = {
        PROGRESS: clamp(score),
        STATE_CONSISTENCY: clamp(B - 0.10 * failed_count),
        TOOL_QUALITY: clamp(B - 0.18 * failed_count - 0.12 * empty_warn - 0.08 * arg_warn),
        EFFICIENCY: clamp(B - 0.10 * extra_user_turns - 0.02 * max(step_count - 12, 0)),
        SAFETY: clamp(B - 0.15 * failed_count),
        INTERACTION_QUALITY: clamp(B - 0.08 * grounding_warn),
        RECOVERY: clamp(B - 0.20 * failed_count),
    }

    if interval.status in {FAIL, MISSING, INVALID}:
        dimension_scores[PROGRESS] = min(dimension_scores[PROGRESS], 0.2)
        dimension_scores[RECOVERY] = min(dimension_scores[RECOVERY], 0.3)

    stage_score = weighted_average(dimension_scores, weights)
    confidence = cheap_confidence(interval.status, missing_ratio, diagnostics)

    return StageEvaluationResult(
        status=interval.status,
        stage_score=stage_score,
        dimension_scores=dimension_scores,
        required_fields_missing_ratio=missing_ratio,
        hard_constraints_all_pass=hard_pass,
        judge_confidence=confidence,
        metadata={"stage_quality_diagnostics": diagnostics},
    )
```

## 11. Standard 级评估算法

`StandardJudge` 是单轮 LLM-as-a-Judge。

### 11.1 Prompt 构造

调用：

```python
prompt = build_judge_prompt("standard", interval, task_case, trajectory, weights, language=language)
```

Prompt context 包含：

| 字段 | 内容 |
|---|---|
| `task.task_description` | 任务描述。 |
| `stage_goal` | 通过 `stage_goal_key(anchor, milestone)` 从 `TaskCase.stage_goals` 解析的阶段目标。 |
| `rubric_dimension_focus` | 当前所有维度列表。 |
| `interval.status` | 当前结构化 milestone 状态。 |
| `interval.evidence` | milestone evidence。 |
| `interval.milestone_score` | milestone 结构化分数。 |
| `structured_milestone_evidence` | 每个 constraint score 的结构化 evidence、actual 摘要和约束上下文。 |
| `steps` | 当前阶段左开右闭区间内的 step 摘要。 |
| `rubric_dimensions` | 7 个评分维度。 |
| `required_output` | JSON 输出 schema。 |

### 11.2 LLM 调用与 JSON 校验

`LLMJudge._call_json(...)`：

1. 构造 system prompt：严格要求只输出 JSON。
2. 调用 `BaseLLM.chat(messages, response_format="json_object")`。
3. 解析完整 JSON 或 fenced JSON block。
4. 校验 payload。

必须字段：

```json
{
  "status": "pass|warn|fail|missing|ambiguous|invalid",
  "dimension_scores": {
    "progress": 0.0,
    "state_consistency": 0.0,
    "tool_quality": 0.0,
    "efficiency": 0.0,
    "safety": 0.0,
    "interaction_quality": 0.0,
    "recovery": 0.0
  },
  "judge_confidence": 0.0,
  "evidence": ["..."],
  "diagnosis": ["..."],
  "metadata": {}
}
```

校验规则：

- `status` 必须是 `StageStatus` 枚举。
- 每个维度分必须存在且为 `[0,1]` 浮点数。
- `judge_confidence` 必须是 `[0,1]`。
- `evidence` 与 `diagnosis` 必须是字符串列表。
- `metadata` 必须是对象或缺省。

### 11.3 结果转换

代码不会信任 LLM 输出的 `stage_score`。即使 LLM 返回，实际也不使用。

阶段分统一由代码计算：

```text
stage_score = stage_score_from_dimensions(validated.dimension_scores, weights)
```

初始不确定性：

```text
uncertainty = 1 - judge_confidence
```

随后在主流程中被统一不确定性公式覆盖。

### 11.4 Standard 级伪代码

```python
def standard_evaluate_stage(interval, task_case, trajectory, weights):
    language = language_from_task(task_case)
    prompt = build_judge_prompt("standard", interval, task_case, trajectory, weights, language)
    input_metadata = judge_input_metadata(...)

    payload = call_llm_and_parse_json(prompt)
    validated = validate_payload(payload)

    stage_score = weighted_average(validated.dimension_scores, weights)
    result = StageEvaluationResult(
        status=validated.status,
        evaluator_level=STANDARD,
        stage_score=stage_score,
        uncertainty=1 - validated.judge_confidence,
        dimension_scores=validated.dimension_scores,
        evidence=validated.evidence,
        diagnosis=validated.diagnosis,
        judge_confidence=validated.judge_confidence,
        metadata=input_metadata + validated.metadata,
    )
    result.metadata.update(judge_result_output_metadata(result, input_metadata))
    return result
```

## 12. Expensive 级评估算法

`ExpensiveJudge` 是多轮 LLM-as-a-Judge。

### 12.1 轮次结构

默认 `expensive_passes=3`。聚焦维度组固定循环：

```python
_FOCUS_GROUPS = (
    "progress,state_consistency",
    "tool_quality,efficiency,recovery",
    "safety,interaction_quality",
)
```

完整调用序列：

1. 执行 `expensive_passes` 次 `expensive_focus` prompt。
2. 执行 1 次 `expensive_risk` prompt。
3. 执行 1 次 `expensive_adjudication` prompt，输入前序 passes。

若 `expensive_passes=3`，总 LLM 调用数为：

```text
3 focus + 1 risk + 1 adjudication = 5
```

### 12.2 Focus pass

每一轮 focus pass：

```python
group = _FOCUS_GROUPS[index % len(_FOCUS_GROUPS)]
prompt = build_judge_prompt(
    "expensive_focus",
    interval,
    task_case,
    trajectory,
    weights,
    extra={"focus_dimensions": group},
    render_kwargs={"focus_dimensions": group},
)
payload = call_json(prompt)
payload["prompt_type"] = "focus"
payload["focus_dimensions"] = group
passes.append(payload)
pass_metadata.append(_pass_metadata(payload, weights, input_metadata))
```

每个中间 pass 也会被 JSON 校验，并用当前动态权重计算一个中间 `stage_score`，写入 metadata 供审计。

### 12.3 Risk pass

Risk pass 使用 `expensive_risk` 模板，重点复核：

- failure boundary。
- safety concern。
- tool exception。
- hard constraint failure。
- earliest error location。
- fatal 或 near-fatal risk。

代码层面它与 focus pass 一样：

```python
risk_payload = call_json(risk_prompt)
risk_payload["prompt_type"] = "risk"
passes.append(risk_payload)
pass_metadata.append(_pass_metadata(...))
```

### 12.4 Adjudication pass

最终裁决 prompt：

```python
adjudicator_prompt = build_judge_prompt(
    "expensive_adjudication",
    interval,
    task_case,
    trajectory,
    weights,
    extra={"previous_passes": passes},
)
payload = call_json(adjudicator_prompt)
```

最终 `StageEvaluationResult` 只由 adjudication payload 生成。

metadata 中会额外包含：

```python
metadata = {
    "judge_passes": pass_metadata,
    **input_metadata,
}
```

### 12.5 Expensive 级伪代码

```python
def expensive_evaluate_stage(interval, task_case, trajectory, weights):
    language = language_from_task(task_case)
    passes = []
    pass_metadata = []

    for index in range(expensive_passes):
        group = FOCUS_GROUPS[index % len(FOCUS_GROUPS)]
        payload = call_json(build_prompt("expensive_focus", focus_dimensions=group))
        payload["prompt_type"] = "focus"
        payload["focus_dimensions"] = group
        passes.append(payload)
        pass_metadata.append(pass_metadata_from_payload(payload, weights))

    risk_payload = call_json(build_prompt("expensive_risk"))
    risk_payload["prompt_type"] = "risk"
    passes.append(risk_payload)
    pass_metadata.append(pass_metadata_from_payload(risk_payload, weights))

    final_payload = call_json(build_prompt(
        "expensive_adjudication",
        previous_passes=passes,
    ))

    result = result_from_payload(
        interval=interval,
        level=EXPENSIVE,
        payload=final_payload,
        weights=weights,
        metadata={"judge_passes": pass_metadata, **adjudication_input_metadata},
    )
    result.metadata.update(judge_result_output_metadata(...))
    return result
```

## 13. 单阶段评估与动态更新的完整算法

`_evaluate_stage(...)` 是动态权重与评估级别策略更新的核心。

完整顺序：

1. 读取当前 policy 的 `effective_level()`。
2. 按级别调用唯一 judge：
   - cheap 调 `CheapJudge`。
   - standard 调 `StandardJudge`，若未配置则抛 `JudgeConfigurationError`。
   - expensive 调 `ExpensiveJudge`，若未配置则抛 `JudgeConfigurationError`。
3. 设置 `stage_result.evaluator_level = level`。
4. 调用 `_enrich_stage_result(...)`：
   - 对全轨迹重新评估 minefields。
   - 计算并覆盖最终 uncertainty。
   - 写入 `minefield_score` 和 `fatal_minefield_score`。
5. 调用 `update_weights(...)` 得到 `next_weights`。
6. 调用 `update_evaluation_policy(...)` 得到 `policy_update`。
7. 写入 stage metadata：
   - `active_evaluation_policy`
   - `next_evaluation_policy`
   - `evaluation_policy_update`
8. 返回 `stage_result, next_weights, policy_update`。

伪代码：

```python
def evaluate_stage(interval, task_case, trajectory, weights, scorer, evaluation_policy):
    level = evaluation_policy.effective_level()

    if level == CHEAP:
        result = cheap_judge.evaluate_stage(interval, task_case, trajectory, weights)
    elif level == STANDARD:
        result = standard_judge.evaluate_stage(interval, task_case, trajectory, weights)
    elif level == EXPENSIVE:
        result = expensive_judge.evaluate_stage(interval, task_case, trajectory, weights)

    result.evaluator_level = level

    matches, minefield_score, fatal_minefield = evaluate_minefields(...)
    result = enrich_stage_result(
        interval=interval,
        result=result,
        minefield_score=minefield_score,
        fatal_minefield=fatal_minefield,
        thresholds=thresholds,
    )

    next_weights = update_weights(
        current=weights,
        scores=result.dimension_scores,
        uncertainty=result.uncertainty,
        config=weight_config,
    )
    result.next_weights = next_weights

    policy_update = update_evaluation_policy(evaluation_policy, result, thresholds)

    result.metadata["active_evaluation_policy"] = policy_update.current_policy.to_dict()
    result.metadata["next_evaluation_policy"] = policy_update.next_policy.to_dict()
    result.metadata["evaluation_policy_update"] = {
        "should_stop": policy_update.should_stop,
        "termination_code": policy_update.termination_code,
        "termination_reason": policy_update.termination_reason,
    }

    return result, next_weights, policy_update
```

## 14. Finish 与 Pending Required 阶段

### 14.1 Finish 阶段

只有自然结束且没有 pending required milestone 时，才生成 finish 阶段。

finish anchor：

```text
finish_anchor_id = graph.metadata["graph_analysis"]["finish_stage_anchor_predecessor_id"] or "__start__"
finish_node_id = graph.metadata["graph_analysis"]["finish_node_id"] or "__finish__"
```

boundary：

```text
if finish_anchor_id == "__start__":
    boundary_index = trajectory.first_step_index - 1
elif finish_anchor_id in matched:
    boundary_index = matched[finish_anchor_id].end_step_index
else:
    boundary_index = max(end_step_index of matched settlements)
```

阶段：

```python
StageInterval(
    stage_id=f"{finish_anchor_id}->{finish_node_id}",
    milestone_id="__finish__",
    stage_anchor_milestone_id=finish_anchor_id,
    start_boundary_step_index=boundary_index,
    start_step_index=stage_start_step_index(...),
    end_step_index=last_step_index,
    status=PASS,
    evidence=["finish 结算节点"],
)
```

finish 阶段会进入 `_append_stage_settlement(...)`，因此同样使用当前评估级别、当前动态权重，并更新下一阶段权重和 policy。

### 14.2 Pending required synthetic stage

自然结束时若存在未完成 required milestone：

1. 构造最终 milestone 诊断。
2. 对每个 required 且未 matched 的 milestone 生成 `StageEvaluationResult`。
3. 阶段 ID 仍使用稳定 key：`stage_goal_key(anchor_id, milestone_id)`。
4. 不追加 finish stage。

状态：

```text
status = FAIL, if ready_ever or attempt_count > 0
status = MISSING, otherwise
```

固定结果：

```text
evaluator_level = CHEAP
stage_score = 0
uncertainty = 1
dimension_scores = {dimension: 0 for all dimensions}
hard_constraints_all_pass = False
required_fields_missing_ratio = 1
metadata.synthetic_pending_required = True
```

## 15. Minefield 扣罚与最终总分

### 15.1 Minefield penalty

最终报告重新扫描全轨迹 minefields，得到 `minefield_matches`。

扣罚比例取所有命中中的最大 penalty：

```text
if penalty.mode == "fixed":
    penalty_i = score_i * penalty.value
else:
    penalty_i = score_i

minefield_penalty_score = clamp(max(penalty_i))
```

### 15.2 总分

若没有 stage reports：

```text
overall_score = 1.0 if minefield_penalty_score == 0 else 0.0
```

否则：

```text
raw_stage_average = average(stage.stage_score for stage in stage_reports)
overall_score = clamp(raw_stage_average * (1 - minefield_penalty_score))
```

### 15.3 Coverage

报告中的 `milestone_coverage`：

```text
if graph has no nodes:
    coverage = "none"
elif all required milestone ids are matched:
    coverage = "full"
else:
    coverage = "partial"
```

若 `matched_settlements` 为空，会从非 missing 且非 synthetic pending 的 `stage_reports` 反推 matched ids。

## 16. 关键行为总结

1. 当前 DynSTEER 是运行期动态评估，不是离线整轨迹后处理。每个新增 step 都可能触发 boundary、minefield 和 milestone checkpoint。
2. 阶段由 milestone DAG 的 `stage_anchor_predecessor_id` 切分，区间语义是 `(anchor_boundary, current_boundary]`。
3. 阶段 ID 固定为 `{anchor}->{milestone}`，finish 为 `{finish_anchor}->__finish__`。
4. 当前阶段只调用一个评估级别，级别由进入阶段前的 policy effective level 决定。
5. 动态权重在阶段完成后更新，核心是“低于目标的维度指数增强 + 不确定性 focus 增强 + 归一化”。
6. 评估级别策略在阶段完成后更新，低分或失败阶段直接触发策略停止，不在同阶段升级到 expensive。
7. 高置信通过会让下一阶段基础级别回到 cheap；一般通过或边界情况会让下一阶段基础级别为 standard。
8. 任一维度低于 fail 阈值会把下一阶段有效级别推到 expensive；低于 warn 阈值会按当前 base level 升一档。
9. CheapJudge 将 milestone 分数只作为 progress 维度，不复制到所有维度；其他维度由阶段状态和轨迹质量诊断扣分生成。
10. StandardJudge 和 ExpensiveJudge 都要求 LLM 输出 7 维分数、状态、置信度、证据和诊断，但阶段总分统一由代码按动态权重计算。
11. ExpensiveJudge 的最终结果只采用 adjudication pass，focus 与 risk pass 作为前置审计材料进入最终裁决。
12. pending required milestone 会合成失败或缺失阶段，不再追加 finish 阶段。
