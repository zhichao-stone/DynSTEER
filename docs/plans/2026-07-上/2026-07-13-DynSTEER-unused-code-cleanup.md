# DynSTEER 未使用代码清理方案

## 1. 修改目标

清理当前 `dynsteer` 代码中可确认未使用的 import、函数、函数参数等冗余内容，降低维护成本，并避免误删对外入口、抽象接口、测试猴补丁入口或动态调用入口。

## 2. 实施范围

- 优先清理 `dynsteer` 包内 Python 代码。
- 测试代码只在存在明显未使用 import 或参数时清理，不主动删除测试辅助函数。
- 不处理当前工作区已有的无关删除、新增和文档改动。

## 3. 实施步骤

1. 使用 AST 扫描生成未使用 import、顶层函数、类方法参数候选。
2. 对候选做人工过滤：
   - 保留抽象方法、协议方法、继承覆写方法。
   - 保留 `__all__`、注册表、CLI/外部可能直接调用的公共入口。
   - 保留测试通过 monkeypatch 或动态 getattr 使用的符号。
3. 使用 `apply_patch` 删除确认冗余的 import、函数、参数。
4. 使用 `uv run python -m compileall dynsteer` 和相关 PyTest 验证。
5. 清理验证生成的 `__pycache__`、`.pytest_cache`、`.uv-cache`。

## 4. 验收标准

- 清理后的代码无语法错误。
- 相关测试通过。
- 本次触及文件 `git diff --check` 通过。
- 仅清理可确认冗余项，不为兼容旧接口额外增加中转函数。

## 附录A. 项目中没有把握实现的模块部分

没有完全无法把握的模块。需要谨慎的是函数是否被外部脚本或动态反射调用：静态扫描无法覆盖这些情况，因此本次只删除内部私有函数、局部 import 或参数中可从调用链明确确认无用的项。
