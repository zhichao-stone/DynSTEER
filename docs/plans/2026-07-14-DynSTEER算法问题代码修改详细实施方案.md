# DynSTEER 算法问题代码修改详细实施方案

> 生成日期：2026-07-14  
> 依据文档：`docs/plans/2026-07-14-DynSTEER算法问题核查报告与代码修订方案.md`  
> 文档定位：本方案是面向代码落地的详细实施计划，暂不直接修改源码。  
> 约束遵循：遵循 `docs/constraints/code.md`；代码落地不主动提交 git；后续实现必须补充 PyTest、API 文档和必要中文注释。

## 1. 修改目标

本轮代码修改要解决三类核心问题：

1. 评估语义问题：milestone 不再有 optional / required 分流语义；所有 milestone 都是必须完成的轨迹约束节点。
2. 逐维评估问题：每个维度有独立评估级别、独立分数、独立置信度、独立不确定度；彻底删除全局 `uncertainty` 和全局 `judge_confidence`。
3. 策略更新问题：动态权重基于每维低分和每维不确定度做指数乘法更新；standard / expensive prompt 只评估目标维度，cheap 规则按维度拆分并补充可解释诊断。

最终代码应达到：

```text
StageEvaluationResult
  dimension_scores: dict[Dimension, float]
  dimension_confidence: dict[Dimension, float]
  dimension_uncertainty: dict[Dimension, float]
```

报告、面板、权重更新、policy 调度都只使用这三个逐维字段，不再读取全局 `uncertainty` / `judge_confidence`。

## 3. 数据模型修改

### 3.1 `StageEvaluationResult`

当前字段：

```python
uncertainty: float
judge_confidence: float
```

必须删除，不做旧报告兼容。

新增字段：

```python
dimension_confidence: dict[Dimension, float]
dimension_uncertainty: dict[Dimension, float]
```

约束：

1. `dimension_scores`、`dimension_confidence`、`dimension_uncertainty` 的 key 必须一致。
2. 最终进入 `TrajectoryEvaluationReport.stage_reports` 的结果必须覆盖全部七维。
3. standard / expensive 的中间 partial 结果可以只覆盖目标维度，但进入最终报告前必须由合并函数补齐为七维完整结果。
4. `to_dict()` 输出：

```json
{
  "dimension_scores": {"progress": 1.0},
  "dimension_confidence": {"progress": 0.95},
  "dimension_uncertainty": {"progress": 0.05}
}
```

不再输出：

```json
{
  "uncertainty": 0.12,
  "judge_confidence": 0.88
}
```

### 3.2 `_ValidatedJudgePayload`

删除：

```python
judge_confidence: float
```

保留：

```python
status: StageStatus
dimension_scores: dict[Dimension, float]
evidence: list[str]
diagnosis: list[str]
metadata: JsonObject
```

调整点：

1. `_dimension_scores(...)` 不再强制覆盖全部 `Dimension`。
2. 校验函数必须接收 `expected_dimensions: set[Dimension]`，只校验目标维度。
3. LLM 输出的 score anchor 建议使用字符串枚举，便于定位 logprob：

```json
{
  "dimension_scores": {
    "tool_quality": "0.75"
  }
}
```

解析后转换为 float。

### 3.3 `DynamicWeightConfig`

当前：

```python
class DynamicWeightConfig:
    alpha: float
    beta: float
    targets: dict[Dimension, float]
    focus: dict[Dimension, float]
```

改为：

```python
class DynamicWeightConfig:
    alpha: float = 1.0
    beta: float = 1.0
```

同步删除：

- `DEFAULT_TARGETS`
- `DEFAULT_FOCUS`
- `default_dynamic_weight_config()` 中的 targets / focus 初始化

说明：任务类型先验仍然由 `TASK_TYPE_WEIGHTS` 提供，动态阶段不再引入 target / focus。

### 3.4 `ThresholdConfig`

当前 `low_uncertainty` / `high_uncertainty` 是全局不确定度阈值，需要改为逐维阈值：

```python
low_dimension_uncertainty: float = 0.2
high_dimension_uncertainty: float = 0.45
```

如果实现时为了命名简洁，也可以统一为：

```python
dimension_uncertainty_warn_threshold: float = 0.45
```

但不要保留全局 `low_uncertainty` / `high_uncertainty`。

### 3.5 LLM 响应模型

当前 `BaseLLM.chat(...) -> str` 不足以支持 token probability。

建议新增模型：

```python
@dataclass(frozen=True)
class LLMTokenLogprob:
    token: str
    logprob: float

@dataclass(frozen=True)
class LLMResponse:
    text: str
    token_logprobs: list[LLMTokenLogprob] = field(default_factory=list)
```

修改 `BaseLLM.chat(...) -> LLMResponse`，并同步更新调用方：

- `dynsteer/stage/__init__.py` 使用 `response.text`
- `LLMJudge._call_json(...)` 使用 `response.text` 和 `response.token_logprobs`

不新增只转发旧返回值的中转函数，避免接口冗余。

## 4. 不确定性与置信度实现

### 4.1 新增 `dynsteer/evaluate/confidence.py`

建议提供函数：

```python
def uncertainty_from_confidence(
    dimension_confidence: dict[Dimension, float],
) -> dict[Dimension, float]:
    ...

def cheap_dimension_confidence(
    dimension_scores: dict[Dimension, float],
    diagnostics: JsonObject,
    status: StageStatus,
    hard_constraints_all_pass: bool,
) -> dict[Dimension, float]:
    ...

def standard_logprob_confidence(
    payload: _ValidatedJudgePayload,
    response: LLMResponse,
    expected_dimensions: set[Dimension],
) -> dict[Dimension, float] | None:
    ...

def agreement_uncertainty(
    payloads: list[_ValidatedJudgePayload],
    expected_dimensions: set[Dimension],
) -> dict[Dimension, float]:
    ...
```

注意：

1. 这些函数是共享算法，不是中转函数，适合集中放在一个文件。
2. 不设计 `dimension_confidence_method` / `raw_signals` 输出字段。
3. 置信度算法由调用级别固定：
   - cheap：`cheap_dimension_confidence(...)`
   - standard：优先 `standard_logprob_confidence(...)`，失败时 `agreement_uncertainty(...)`
   - expensive：固定 `agreement_uncertainty(...)`

### 4.2 cheap 置信度

最低限度实现：

| 维度 | confidence 规则 |
|---|---|
| `progress` | hard constraint 明确 pass/fail 且 selector 命中时为高置信；缺失是确定性失败，不是高不确定。 |
| `tool_quality` | 基于工具失败、参数 warning、空结果 warning 的结构化信号；只有启发式 warning 时置信度略低。 |
| `efficiency` | 有 `expected_step_budget` 时置信度较高；仅 fallback 固定阈值时置信度较低。 |
| `safety` | minefield / policy warning 明确时高置信；仅工具失败代理时低置信。 |
| `interaction_quality` | 只基于 grounding warning / extra user turn 做弱信号，置信度中等偏低。 |
| `recovery` | 有 unrecovered failure 计数时中高置信；没有失败时默认中性高置信。 |

### 4.3 standard 置信度

默认路径：

1. 单次 LLM 调用，请求 logprobs。
2. prompt 要求 status 和 score anchor 使用离散枚举。
3. 计算：

```text
p_status = probability(selected_status_token)
p_score_d = probability(selected_score_anchor_token_for_dimension_d)
dimension_confidence_d = sqrt(p_status * p_score_d)
dimension_uncertainty_d = 1 - dimension_confidence_d
```

fallback：

1. 如果 provider 不支持 logprobs，捕获明确异常或检测 `response.token_logprobs` 为空。
2. 低温重复调用 K=3。
3. 用 status / score anchor 分布熵计算：

```text
U_status = H(p_status) / log(|StageStatus|)
U_score_d = H(p_score_d) / log(5)
dimension_uncertainty_d = max(U_status, U_score_d)
dimension_confidence_d = 1 - dimension_uncertainty_d
```

### 4.4 expensive 置信度

对每个 expensive 维度独立 K=3：

```text
for dimension in expensive_dimensions:
    payloads = [judge_once(dimension) for _ in range(3)]
    score = aggregate_score_anchor(payloads)
    confidence = 1 - agreement_uncertainty(payloads, {dimension})[dimension]
```

聚合规则：

1. score 采用多数 anchor；若无多数，取平均后映射到最近 anchor。
2. status 采用多数 status；若无多数，按风险优先级 `fail > missing > invalid > ambiguous > warn > pass`。
3. evidence / diagnosis 合并前三条去重文本，避免报告过长。

## 5. 动态权重更新

删除旧公式：

```text
w_next ∝ w * exp(alpha * max(0, target - score) + beta * global_uncertainty * focus)
```

新增公式：

```text
loss_d = clamp(1 - dimension_scores[d])
u_d = clamp(dimension_uncertainty[d])
raw_next_weight_d = current_weight_d * exp(alpha * loss_d + beta * u_d)
next_weight_d = raw_next_weight_d / Σ_j raw_next_weight_j
```

实现修改：

```python
def update_weights(
    current: dict[Dimension, float],
    scores: dict[Dimension, float],
    dimension_uncertainty: dict[Dimension, float],
    config: DynamicWeightConfig | None = None,
) -> dict[Dimension, float]:
    ...
```

metadata 建议记录在 `StageEvaluationResult.metadata["weight_update_diagnostics"]`：

```json
{
  "loss_by_dimension": {},
  "uncertainty_by_dimension": {},
  "exponent_by_dimension": {},
  "raw_next_weight_by_dimension": {},
  "normalized_delta": {},
  "dominant_dimension": "tool_quality"
}
```

这属于权重更新诊断 metadata，不是置信度原始信号。

## 6. 逐维评估调度与结果合并

### 6.1 评估器接口

建议修改 `BaseJudge.evaluate_stage(...)`：

```python
def evaluate_stage(
    self,
    interval: StageInterval,
    task_case: TaskCase,
    trajectory: Trajectory,
    weights: dict[Dimension, float],
    dimensions: set[Dimension] | None = None,
) -> StageEvaluationResult:
    ...
```

含义：

1. `dimensions is None` 表示评估全部维度。
2. standard / expensive 必须只输出 `dimensions` 中的维度。
3. cheap 可以计算全部维度，也可以按传入维度裁剪。

### 6.2 分组执行

新增 helper，建议放在 `dynsteer/evaluate/policy.py`：

```python
def dimensions_by_level(policy: EvaluationPolicyState) -> dict[EvaluationLevel, set[Dimension]]:
    ...
```

阶段执行逻辑：

```text
cheap_dimensions = dimensions_by_level[cheap]
standard_dimensions = dimensions_by_level[standard]
expensive_dimensions = dimensions_by_level[expensive]

cheap_result = cheap_judge.evaluate_stage(..., dimensions=all_dimensions)
standard_result = standard_judge.evaluate_stage(..., dimensions=standard_dimensions)
expensive_result = expensive_judge.evaluate_stage(..., dimensions=expensive_dimensions)

final_result = merge_dimension_results(cheap_result, standard_result, expensive_result)
```

合并规则：

1. cheap 先作为全维 baseline。
2. standard 覆盖 standard 维度。
3. expensive 覆盖 expensive 维度。
4. `dimension_scores` / `dimension_confidence` / `dimension_uncertainty` 同步覆盖。
5. `status` 由 status aggregation policy 生成：
   - `progress` fail / missing 可让阶段 fail。
   - `safety` fail 可让阶段 fail。
   - 其他维度低分进入 diagnosis、weights、policy，不直接把 milestone 改为 unmatched。

## 7. Judge 与 Prompt 修改

### 7.1 `LLMJudge`

主要修改：

1. `_call_json(...)` 返回：

```python
tuple[JsonObject, LLMResponse]
```

或返回小 dataclass：

```python
class JudgeCallResult:
    payload: JsonObject
    response: LLMResponse
```

2. `_validate_payload(payload, expected_dimensions)` 支持 partial dimensions。
3. `_result_from_payload(...)` 必须接收：
   - `expected_dimensions`
   - `dimension_confidence`
   - `dimension_uncertainty`
4. 不再读取 payload 中的 `judge_confidence`。

### 7.2 `StandardJudge`

流程：

1. 构造目标维度 prompt。
2. 调用 LLM，默认传入：

```python
response_format="json_object"
logprobs=True
top_logprobs=5
```

3. 如果返回 logprobs 可用，使用 token probability 计算置信度。
4. 如果 provider 不支持 logprobs：
   - 重复 K=3；
   - 使用 agreement entropy；
   - 不记录方法字段，只按固定 fallback 算法返回结果。

### 7.3 `ExpensiveJudge`

删除当前 `_FOCUS_GROUPS` 和 risk/adjudication 组合流程。

改为：

```text
for dimension in expensive_dimensions:
    run dimension-specific prompt K=3
    aggregate one dimension result
merge dimensions
```

模板目录：

```text
dynsteer/prompt/templates/judge/expensive/
  progress.zh.md
  state_consistency.zh.md
  tool_quality.zh.md
  efficiency.zh.md
  safety.zh.md
  interaction_quality.zh.md
  recovery.zh.md
```

如暂时不想一次写 14 个中英文模板，可先保留一个通用 expensive 模板，但必须通过 `rubrics` 只传入单维，输出也只允许单维。长期再拆成逐维模板。

## 8. CheapJudge 规则级评估

### 8.1 质量诊断扩展

在 `dynsteer/evaluate/quality.py` 中补充：

| 字段 | 含义 |
|---|---|
| `expected_step_budget` | task family / adapter 给出的期望步数预算；缺失时用 fallback 12，但标注为 fallback。 |
| `policy_warnings` | policy / safety 相关结构化 warning。 |
| `unrecovered_failure_count` | 失败工具调用后未出现成功重试、解释、降级或停止的次数。 |
| `missing_expected_tool_call` | 阶段目标明显需要工具但未出现工具调用。 |
| `result_not_used` | 工具返回后 agent 未引用或未处理结果即断言完成。 |

这些字段都可以从现有 steps / tool_call / tool_result / grounding warning 中低成本推断，不需要引入 LLM。

### 8.2 维度分数最小改动

保留当前 `CheapJudge._dimension_scores(...)` 的结构，但将扣分项改为更细：

```text
progress = milestone_score.score
state_consistency = base - failed_tool_penalty - empty_state_penalty - grounding_penalty
tool_quality = base - failed_tool_penalty - argument_penalty - empty_result_penalty - result_not_used_penalty
efficiency = base - extra_user_turn_penalty - step_budget_overhead_penalty
safety = base - minefield_or_policy_penalty - weak_failed_tool_proxy_penalty
interaction_quality = base - grounding_penalty - extra_user_turn_penalty
recovery = base - unrecovered_failure_penalty
```

### 8.3 维度置信度

新增 cheap 逐维 confidence helper：

```python
def _dimension_confidence(
    self,
    status: StageStatus,
    missing_ratio: float,
    hard_pass: bool,
    diagnostics: JsonObject,
) -> dict[Dimension, float]:
    ...
```

约束：

1. hard fail / missing 是确定性结果，不自动降低 `progress` confidence。
2. fallback step budget 会降低 `efficiency` confidence。
3. interaction / recovery 若只有弱模式信号，confidence 不应过高。

## 9. Milestone 与 Operator 清理

### 9.1 删除 `Milestone.required` 算法语义

修改点：

- `dynsteer/model.py`：删除 `Milestone.required` 字段。
- `dynsteer/adapter/loader.py`：读取 milestone 时如果发现 `required=false`，按新接口报错。
- `dynsteer/adapter/toolsandbox/utils/convert.py`：`_matcher_nodes(..., required: bool)` 改名，例如 `kind: Literal["milestone", "minefield"]`。
- `dynsteer/evaluate/matching/frontier.py`：`required_ready_milestone_ids` 改为 `ready_milestone_ids`。
- `dynsteer/evaluate/runtime.py`：`pending_required_stage_results` 改为 `pending_milestone_stage_results`。
- `dynsteer/evaluate/evaluator.py`：coverage 用全部 `graph.nodes`。

### 9.2 删除 `Operator.AST_MATCH`

修改点：

- `dynsteer/model.py` 删除枚举。
- `adapter/loader.py` 如果读到 `ast_match`，报错提示当前不支持。
- `docs/apis/constraints.md` 不列该 operator。
- 测试确保 unknown / removed operator 会报错，而不是默认 0 分。

### 9.3 修复 delta reference source

修改点：

- `GeneralScorer.constraint_sources(...)` 不再用 `snapshot.snapshot_id == reference_milestone_id`。
- 从 `ScoringContext.matched_snapshots[reference_milestone_id]` 获取 reference snapshot。
- 没有 reference snapshot 时返回 missing / diagnostic。

## 10. Policy 与报告/面板

### 10.1 Policy 更新

删除：

```python
result.uncertainty <= thresholds.low_uncertainty
```

改为逐维：

```text
dimension should upgrade if:
  score_d < warn_threshold
  or dimension_uncertainty_d >= high_dimension_uncertainty
```

下一阶段调度：

```text
progress/safety fail -> 可触发阶段 fail 或 stop
低分维度 -> 升级到 standard/expensive
高不确定维度 -> 升级到 standard/expensive
高分低不确定维度 -> 可降回 cheap
```

### 10.2 Report / dashboard

需要更新：

- `TrajectoryEvaluationReport.to_dict()`
- `StageEvaluationResult.to_dict()`
- `docs/apis/evaluate.md`
- `docs/apis/judges.md`
- `docs/apis/display.md`
- `tests/test_display_index_static.py`

展示结构：

```json
"dimension_scores": {},
"dimension_confidence": {},
"dimension_uncertainty": {}
```

面板不再展示全局 uncertainty / judge_confidence。

## 11. 实施顺序

### Phase 1：模型和旧字段删除

1. 修改 `StageEvaluationResult`、`DynamicWeightConfig`、`ThresholdConfig`、`_ValidatedJudgePayload`。
2. 删除旧 `compute_uncertainty(...)`。
3. 修复所有构造 `StageEvaluationResult(...)` 的调用点。
4. 更新 `to_dict()` 和 API 文档。

验收：

- `rg "judge_confidence|uncertainty"` 不应在新字段外出现旧全局语义。
- 所有 stage report JSON 都有三组逐维字段。

### Phase 2：LLM logprobs 与 payload 校验

## 附录A. 项目中没有把握实现的模块部分

1. standard token probability 的跨 provider 稳定性  
   没有完全把握的原因：OpenAI-compatible endpoints 对 `logprobs` 支持不完全一致。方案中已设置 fallback K=3，但不同 provider 的 token 切分可能影响 score anchor probability 提取，需要测试覆盖。

2. expensive 逐维 prompt 的评分稳定性  
   没有完全把握的原因：单维 prompt 的 rubric 质量需要真实失败样例迭代。首版可以用通用模板 + 单维 rubric，后续再拆成每维专门模板。

3. cheap 规则级评估的阈值  
   没有完全把握的原因：`expected_step_budget`、`unrecovered_failure_count` 等规则虽然有论文/benchmark 思路支撑，但具体扣分系数仍需要本项目 run 数据校准。

4. 删除 `Milestone.required` 对历史 adapted case 的影响  
   没有完全把握的原因：当前仓库没有完整历史 adapted case 样本。若外部已有缓存 JSON，删除字段后需要重新生成或显式报错处理。

5. partial dimension status aggregation  
   没有完全把握的原因：`progress` / `safety` 对阶段整体状态应有更高优先级，但 `efficiency` / `interaction_quality` 是否影响整体 pass/fail 需要结合论文实验目标确认。首版建议按本文第 6.2 节规则实现，并在测试中固定行为。
