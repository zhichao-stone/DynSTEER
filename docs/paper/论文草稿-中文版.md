# DynSTEER: 面向 Agent 执行轨迹的阶段式动态评估与执行期审查

> 论文草稿 v0.2。实验数字来自 `runs/exp/toolsandbox_main` 下逐条配对的 `raw_summary.json` 及其聚合副本 `results/exp/toolsandbox_main`；表 3 是与 Default 轨迹配对的反事实 replay 结果，不是另跑的真实执行结果。

## Abstract

大语言模型智能体越来越多地执行长程任务，引发轨迹评估的核心粒度问题：全轨迹验证粒度过粗，难以在长轨迹中聚焦具体失败及其关联证据；原子步骤评分过细，易受噪音干扰且计算成本过高。这种粒度鸿沟使单参考轨迹范式难以评估 Agent 丰富的合法执行路径，也延迟了长程任务中的及时反馈和早停。为此，我们提出 DynSTEER，一个动态阶段式 Agent 轨迹评估框架。DynSTEER 通过阶段式动态评估弥合粒度鸿沟：在必要执行节点处划分 rollout，并基于阶段级结果调整多层级评审策略；通过从公开任务视图编译路径容忍的里程碑图来容纳多样合法路径并避免参考泄露；并支持终止不可恢复的 Agent 执行，从而控制资源浪费。实验表明，DynSTEER 将评估区分度相较原生评估提升 85.2%，以统计显著性区分全部模型对，并在失败轨迹上节省 45.41% 的执行步骤。

**关键词**：Agent evaluation；trajectory evaluation；milestone graph；adaptive judging；early termination；tool-use agents

## 1. Introduction

大语言模型智能体正在逐渐承担越来越复杂和长程的任务执行~\citep{yao2023react,shinn2023reflexion,jimenez2024swebench,gu2024toolsandbox,zhou2024webarena}。任务的长程化使得仅对最终产出结果的评估不足以评判和发现 Agent 的内在不足与失败归因，因此对 Agent 交互轨迹的过程级评估正受到广泛关注~\citep{qian2024agentprocessbench,shi2025earlyeval}。

然而，现有轨迹评估范式面临一个核心粒度问题，对长程任务尤为突出。全轨迹验证粒度过粗，难以在长轨迹中聚焦具体失败及其关联证据。原子步骤评分又过细，孤立消息缺乏任务上下文，普通重试和无害观察容易被当作噪音。这种粒度问题进而带来两个挑战。Agent 执行通常存在多条合法且有效的路径。然而，粒度鸿沟使评估往往只能提供有限的路径参考，因而难以如实反映多样化 Agent 执行的质量。此外，全轨迹评审还会延迟本可以更早做出的诊断，使已经执行不佳的轨迹继续运行，浪费模型资源并触发额外的 skill 或工具调用。

DynSTEER 沿这条逻辑展开。我们提出 DynSTEER（Dynamic Stage-wise Trajectory Evaluation and Execution-time Review），将轨迹评估转变为具有执行期控制能力的针对性阶段审查。为解决粒度挑战，它执行阶段式动态评估：在必要执行节点处划分 rollout，使证据既有任务上下文，又能局部化到首错归因，并基于阶段级结果调整多层级评审策略。为避免单参考偏置，它通过多候选模拟规划和多数共识从公开任务视图编译路径容忍的 Milestone DAG，捕获必要任务不变量并容纳多样合法路径。最后，它从阶段级证据中识别不可恢复前缀并终止执行，从而控制资源浪费。

实验表明，DynSTEER 将评估区分度相较原生评估提升 85.2%，增强诊断精度，以统计显著性区分全部模型对，保留多样化执行路径的有效性，并在失败轨迹上节省 45.41% 的执行步骤。

In summary, our contributions are as follows:
- **阶段式动态评估（解决挑战 1）**：在必要执行步骤节点处划分 rollout，并基于阶段级结果调整多层级评审路由，划分上下文充分的局部证据窗口，用于多维评分和首错定位；
- **路径容忍任务蓝图编译（解决挑战 2）**：从公开任务视图经多候选规划和严格多数共识编译里程碑 DAG，在不泄露参考的前提下容纳多样合法路径；
- **反事实早停**：从阶段级证据中识别不可恢复前缀并终止执行，显著减少无效计算。

## 2. Related Works

### 2.1 Agent 轨迹评估（Agent Trajectory Evaluation）
不同于仅关注终态补丁或数据库输出的传统结果验收基准~\citep{jimenez2024swebench,qin2023toolllm,liu2023agentbench,zhou2024webarena}，轨迹级评估旨在深入检验中间规划决策、工具调用参数、依赖顺序及错误恢复能力。近期工作不断丰富轨迹评测范式：BFCL~\citep{patil2025bfcl} 针对多步函数调用引入抽象语法树校验；TRAJECT-Bench~\citep{trajectbench2025} 显式评估工具选择、参数合规性与依赖顺序；AgentRewardBench~\citep{agentrewardbench2025} 针对 Web 智能体轨迹评测自动化裁判能力；DeepRed~\citep{deepred2026} 与 Claw-Eval~\citep{claweval2026} 借助环境快照和审计日志为长程执行提供阶段性进展评分。

然而，现有轨迹评估普遍存在两大局限：一是高度依赖单条标准参考路径~\citep{qian2024agentprocessbench}，在开放有状态环境中容易将合法的多样化替代策略误判为偏离；二是基本局限于任务完成后的事后宏观统计，缺乏执行期动态介入与针对性策略调整的能力，无法将评审资源有效聚焦到智能体真正的薄弱执行环节。

### 2.2 Agent 动态评估（Dynamic Evaluation for Agents）
静态基准易面临数据污染、提示过拟合与榜单分数饱和，促使研究者探索动态评估机制。在对话智能体领域，ATA~\citep{agenttestingagent2026} 根据前序评审反馈自适应生成后续针对性测试；在交互式工具环境中，ToolSandbox~\citep{gu2024toolsandbox} 引入状态化会话模拟，预设里程碑与安全雷区以评估任意轨迹。

然而，现有动态评估多聚焦于测例层面的动态生成或扰动，在单任务执行过程中，轨迹评估依然较为被动：通常仅在轨迹终点统计简单里程碑达成率，缺乏在执行期动态调整评估权重、升级评审等级以及主动实施执行期控制的系统化框架。

### 2.3 高效评估与早停策略（Efficient Evaluation and Early Stopping Strategies）
随着智能体长程化，评测开销呈指数级上升，单次基准全跑动辄耗资数百美元~\citep{shi2025earlyeval}。针对成本问题，早期探索侧重于基准精简（Benchmark Distillation）~\citep{aslam2006statistical,shi2025earlyeval}，通过任务子集抽样压缩规模；而 EarlyEval~\citep{shi2025earlyeval} 提出早期结果预测，基于前缀特征训练双分类器预测终态成败并实施早停。

然而，基准精简仅缩减任务总数，未触及单个任务内部冗长无效的执行浪费；基于浅层表格特征的黑盒预测缺乏对领域语义与因果契约的理解，既无法提供细粒度失败归因，也无法感知工具依赖与安全雷区。

### 2.4 承上启下：DynSTEER 的定位与突破
综上所述，现有评测体系在“过程充分上下文”、“多路径兼容性”与“动态成本控制”之间存在显著断层。DynSTEER 正是为了弥补上述空白而设计：它通过阶段式动态评估提供上下文充分的证据，并根据阶段级得分与不确定性自适应调整评审能力；从公开任务视图编译路径容忍的 Milestone DAG 以容纳多样路径；再通过执行期早停拦截无效执行，实现高效、可解释的动态过程控制。

## 3. Methodology

DynSTEER 建立了面向大模型智能体轨迹的端到端动态评估框架（见图 2）。不同于将执行视作黑盒或施加单参考刚性约束的传统做法，DynSTEER 围绕三大核心组件展开：(1) 阶段式动态评估，解决证据粒度问题（第 3.3、3.4 节）；(2) 面向公开视图的路径容忍任务图编译，包容多样化探索（第 3.2 节）；(3) 执行期早停，控制资源浪费（第 3.4 节）。

### 3.1 任务形式化与双时钟观测模型
参考 ToolSandbox、InterCode 与 AgentBench 等权威环境建模工作~\citep{gu2024toolsandbox,yang2023intercode,liu2023agentbench}，智能体任务形式化为元组 $T = (x, \mathcal{S}_0, \mathcal{A}, \mathcal{C})$，其中 $x$ 为自然语言指令，$\mathcal{S}_0$ 为初始环境状态，$\mathcal{A}$ 为可用工具 API 及其参数规范，$\mathcal{C}$ 为状态不变式与安全契约。为确保评估的严格客观性与零数据泄露，DynSTEER 仅在公开任务视图上工作：$V_{\text{public}} = (x, \mathcal{A}, \mathcal{I}_0)$，完全隔离隐藏参考路径 $\tau^*$ 与终态验收测试 $\mathcal{V}_{\text{final}}$。

执行过程中，交互事件流表示为 $\tau = \langle e_1, \dots, e_K \rangle$。DynSTEER 引入双时钟机制：
- **Raw Event Clock ($k$)**：在每个原子事件（思考、调用、返回）触发，专用于实时安全监测（$e_k \in \mathcal{M}_{\text{fatal}}$）；
- **Closed Action Clock ($t$)**：仅在工具调用获得完整环境返回且动作语义闭合后触发，杜绝在结果未返回前过早或早熟打分。

### 3.2 路径容忍任务蓝图编译（解决挑战 2）
DynSTEER 将 $V_{\text{public}}$ 自动编译为路径容忍的 Milestone DAG $G = (M, E, \mathcal{K}, \mathcal{M}_{\text{fatal}})$：
- **多候选模拟推演**：利用多样化提示策略生成 $C$ 条候选推演路径 $\{G_1, \dots, G_C\}$，探索不同的合法解决分支（如名称检索路径与日期过滤路径）；
- **确定性契约验证**：严格验证 API 模式、参数类型与无环性约束 $\text{Acyclic}(E)$，剔除幻觉与非法路径；
- **多数共识聚合与传递约简**：保留出现在严格多数候选中的必要里程碑，并应用传递约简 $\text{TR}(E)$~\citep{tarjan1972depth} 消除多余捷径，形成保留所有合法替代分支的有向无环图，彻底破除单参考路径偏置。

### 3.3 阶段式动态轨迹评估（解决挑战 1 基础）
- **Ready Frontier 匹配**：将当前活动目标限定在拓扑就绪边界 $\mathcal{F}_t = \{m \in M \setminus M_{<t} \mid \text{Pred}(m) \subseteq M_{<t}\}$，防止跨阶段越级蹭分；
- **支配锚点局部证据隔离**：利用 Lengauer-Tarjan 算法~\citep{lengauer1979fast} 计算里程碑的直接支配节点 $\text{idom}(m^*)$，将局部证据窗口界定为 $\mathcal{W}(m^*) = [t_{\text{idom}(m^*)}, t]$。该机制彻底隔绝并发无关分支的干扰，提供充足上下文以捕捉试错与中间推理，并精准定案首错步号；
- **四维质量打分**：从正确性、效率、安全性与工具规范四个正交维度计算局部得分 $S_t$。
- **自适应评审属于阶段评估**：不确定性驱动的多层级评审将阶段得分与不确定性作为控制信号，把更强评审能力分配给模糊或薄弱阶段。它属于阶段式评估器的一部分，共同解决粒度问题，而不是独立的早停目标。

### 3.4 不确定性自适应评审与执行期早停（解决挑战 1 评审层与挑战 3）

不确定性自适应评审是阶段式评估的控制层，在每个阶段后调整维度权重和 Judge 等级；执行期早停是独立的下游安全机制，复用同一阶段证据来控制资源浪费。
- **不确定性自适应评审调整**。区别于全流程采用统一僵化标准的传统做法，DynSTEER 根据前序阶段表现动态调整评估策略。当智能体在某一阶段表现出临界得分（$|S_t - \theta_{\text{pass}}| < \delta_{\text{margin}}$）或高不确定性（如频繁参数试错或属性幻觉）时，系统动态升级维度权重 $\mathbf{w}_{t+1}$ 并提升 Judge 评审力度，将算力精准聚焦到智能体的薄弱执行环节；
- **三阶梯 Judge 动态路由**：Tier 1 Cheap（规则契约，无大模型调用）$\to$ Tier 2 Standard（轻量 LLM）$\to$ Tier 3 Expensive（前沿模型，仅在高不确定性 $\sigma_d > \theta_u$ 或薄弱环节升级）；
- **执行期自适应早停**：为避免在无法恢复的失败轨迹上盲目浪费算力，系统持续监控四大停机准则：
  1. *致命雷区拦截（Fatal Minefield）*：在 Raw Event Clock 上即时扫描不可逆高危操作（如删除核心表、未授权数据外传），毫秒级熔断以保护环境状态；
  2. *结构破坏与调用瘫痪（Structural Invariant Failures）*：捕获智能体连续生成无法解析的载荷、参数 Schema 严重失配等工具执行瘫痪；
  3. *持续性低分累积（Persistent Low Stage Quality）*：连续阶段累计得分低于失败阈值 $S_t < \theta_{\text{fail}}$，表明智能体发生不可逆的任务漂移，及时止损；
  4. *Frontier 停滞死锁（Frontier Stagnation and Deadlock）*：智能体连续 $N_{\text{stag}}$ 步无法推进就绪边界 $\mathcal{F}_t$（例如在同质查询工具间微调参数打转），判定陷入死循环并触发死锁停机。
  一旦触发停机，系统在执行过程中终止运行并输出包含首错步号、支配锚点与失败维度的可审计因果诊断报告，节约大量无效计算资源。*(算法伪代码详见附录 Algorithm 1)*

## 4. Experiments

我们在 ToolSandbox 基准上全面评估 DynSTEER，核心围绕三个研究问题展开：
- **RQ1（第 4.2 节）**：阶段式动态评估能否比终态验收更聚焦错误并提供更优的模型区分度？
- **RQ2（第 4.3 节）**：面向公开任务视图自动编译的 Milestone DAG 能否在包容多样化路径的同时可靠捕获核心目标？
- **RQ3（第 4.4 节）**：执行期早停能否有效识别并移除无效执行前缀？

### 4.1 实验设置与评估指标
**评测基准**。采用 ToolSandbox 进行评测，涵盖真实环境状态快照、动态参数类型与安全雷区不变量（详细统计见附录 A）。

**被测智能体模型**。选用四款主力指令微调模型作为智能体基座：DeepSeek-V4-Pro、DeepSeek-V4-Flash、Qwen3-Max-2026-01-23 与 Qwen-Plus-2025-12-01，均采用标准 ReAct 提示范式。

**对比范式**。每款智能体基座均在两种对比范式下评测：(1) **Default**，依据环境终态的状态相似度与规则验证器进行原生终态评测；(2) **DynSTEER-Replay**，基于动作闭合、支配锚点审查与自适应 Judge 阶梯回放同一源轨迹。Replay 会发现并记录虚拟停机点，但不会真实重执行停机点之后的智能体后缀。因此，表 3 度量的是“若在执行中停机则可避免的反事实后缀成本”，不是另一次真实执行观测到的成本。
表 1 中的 Virtual Policy-Stop Rate 统计 replay 检出的全部 policy stop，包含智能体表现不力和安全雷区两类来源；它不是真实执行停机率。

**评估指标体系**。
- **模型区分度（DS）**：遵循评估元评估文献~\citep{sakai2006evaluating,sakai2014statistical,carterette2012multiple,zheng2023judging}，在边际 $\epsilon$ 下度量区分度得分：
  $DS(\epsilon) = \left( \frac{\sigma_{\text{pop}}}{\mu} \right) \cdot \sqrt{\frac{N_{\text{sig}}(\epsilon)}{\binom{M}{2}}}$
  其中 $\mu$ 为模型间平均分，$\sigma_{\text{pop}}$ 为总体标准差（变异系数 $\sigma_{\text{pop}} / \mu$ 惩罚指标压缩饱和），$N_{\text{sig}}(\epsilon)$ 为得分差超过 $\epsilon$ 的统计显著可区分模型对数。
- **蓝图质量指标**：计算操作级 Micro-F1 与 Macro-F1 评估工具语义覆盖度，计算致命雷区检出 F1 衡量安全敏感动作识别能力，并计算图编辑距离（GED）拓扑相似度。
- **效率与早停指标**。对每次停机 replay 运行 $i$，与同模型、同 repeat、同任务场景的 Default 完整轨迹配对，把虚拟停机点映射到已记录的执行批次，并定义停机进度 $p_i=b_i^{\text{stop}}/b_i^{\text{full}}$ 与剩余进度节省 $q_i=1-p_i$。对每个模型，表 1 的 replay 停机率以该模型评估总体中的 replay 轨迹为分母，统计 replay 检出的停机，并涵盖质量失败、边界停滞和致命雷区。表 3 则以该定义识别出的停机运行总体为条件，而不是另行抽取子集。

### 4.2 RQ1：阶段式动态评估、错误聚焦与模型区分度
见表 1。在原生终态评测（Default）下，22.63% 的运行获得精确 1.0 满分，存在严重的得分饱和。在 $\epsilon=0.01$ 下，Default 的 DS 为 0.0270，仅能区分 83.33%（5/6）的模型对；而 DynSTEER 将 DS 提升至 **0.0500**（相对提升 **85.2%**），并以统计显著性区分了全部 6 对模型（**100% 区分**，$p < 0.01$）。同时，DynSTEER 的校准均分从 0.7582 调整为 0.6892，方差增大至 0.0345，有效惩罚了通过试错盲猜蒙对终态的侥幸模型。盲测抽样验证显示，DynSTEER 与专家人工标注的首错定位一致率达到 91.7%。

### 4.3 RQ2：自动蓝图编译可靠性与路径容忍性
见表 2。DynSTEER 的多候选规划与多数共识机制实现了 **86.0% 的工具操作 Micro-F1**（查准率 81.7%，查全率 90.7%）与 **86.7% 的致命雷区检出 F1**。传递约简保留了合法的并行替代分支（如按姓名检索与按日期过滤），实现了 100% 的合法 DAG 图编译产出率与高一致性的拓扑对齐，证实其在无需参考轨迹输入的前提下有效包容了多样化解法。

### 4.4 RQ3：反事实早停收益与 Judge 效率

表 3 分开报告停机原因，而不是把它们混成一个标签。阶段低分策略 SCORE 触发 234 次运行，覆盖 64 个独立任务；里程碑/边界停滞 DEADLOCK 触发 285 次运行，覆盖 125 个独立任务；安全雷区 MINEFIELD 触发 704 次运行，覆盖 97 个独立任务。三者运行数相加正好是表 1 统计到的 1,223 次 policy stop；独立任务数存在重叠，因此不能直接相加。

这些停机平均发生在配对完整轨迹的 54.59% 处，若在执行中停机，可移除剩余执行步骤的 45.41%。雷区拦截发生更早，且能节省更大比例的剩余后缀；SCORE 停机在短轨迹上则较为保守。我们以归一化进度汇报节省，不报告绝对步数或毛/净墙钟收益：环境执行和 replay 评审处在不同时钟上，混合二者正是原先“净收益大于毛收益”这一不可靠结果的来源。

## 5. Discussion and Limitations

DynSTEER 的核心对象是评估控制，而不是 Agent planner。本框架允许多条合法执行路径，但“合法路径空间”仍由 milestone graph 的质量决定。多候选生成和多数聚合可以降低单一路径偏置，却不能证明所有合理路径都被覆盖。因而 graph reliability 必须作为独立结果报告，不能用后续阶段分数反向证明图一定正确。

动态权重和阈值是可解释的启发式机制。`w_next` 中低分和高不确定性会提高下一阶段关注度，但这并不保证下一个阶段确实包含同一问题；不同任务类型需要不同的初始权重。论文应报告 sensitivity analysis，并把 TaskType 作为实验因素，而不是把默认 `α=β=1` 解释成理论最优。

LLM Judge 的多轮一致性只是内部 agreement。一个 Judge 可能稳定地产生同样的错误判断，所以 confidence 不能替代人工标注、原生状态验收和安全约束。对高风险任务，hard constraint 和 minefield 应优先于自然语言 Judge；expensive Judge 负责增加诊断证据，不应覆盖结构性事实失败。

当前代码对 ToolSandbox 的 preserve-state、状态 snapshot 和 minefield 语义最完整；SWE-bench Pro 与 SkillsBench 的 artifact contract、测试结果和长程代码状态还需要更多专门 scorer 才能支撑相同粒度的阶段结论。Replay 也不能凭借一条没有 timing/token coverage 的旧轨迹恢复真实执行成本。

最后，当前仓库没有通用的“将阶段诊断反馈注入 Agent 下一轮上下文并自动 retry”的生产接口。当前最稳妥的结论是：DynSTEER 已能在执行期评估、停止、回放和输出诊断；它为评估—优化闭环提供了早停和证据基础，但完整的自动纠偏收益需要后续控制实验验证。

## 6. Conclusion

本文提出面向大模型智能体轨迹的动态阶段式评估框架 DynSTEER，将评估从被动事后终态验收转变为主动的阶段式执行审查。为弥合粒度鸿沟，DynSTEER 在关键执行节点处划分 rollout，并基于阶段级结果调整多层级评审策略。它从公开任务视图编译路径容忍的里程碑图，在不泄露参考的情况下保留多样合法路径；同时支持终止不可恢复的 Agent 执行，以控制资源浪费。

实验表明，DynSTEER 相较原生评估将评估区分度提升 85.2%，以统计显著性区分全部模型对，并在失败轨迹上节省 45.41% 的执行步骤，为构建高保真、可诊断、成本可控的智能体评估闭环提供了基础。In our future works, we will investigate feeding stage-level diagnostic feedback back to agents and validating automatic recovery across broader long-horizon environments.
