## 0. 论文定位与建议标题

建议英文标题：**DynSTEER: Dynamic Stage-wise Trajectory Evaluation and Execution-time Review for Agents**

建议中文标题：**DynSTEER：面向 Agent 执行轨迹的阶段式动态评估与执行期审查**

论文的主张应集中在“评估器如何沿着真实轨迹动态地产生更有区分度、更可诊断、成本更可控的结果”，而不是泛化为一个已经完成 Agent 自动优化的系统。当前代码已经实现执行期评估、停止和 replay；将诊断反馈注入 Agent 并自动重试的闭环应作为后续扩展或单独实验。

- **排版与符号约束**：严禁出现任何圆括号及方括号类注释符号（包括缩写括号、编号括号和占位括号），句式紧凑自然、多变且富有逻辑推进感。

### 1.2 逻辑组织架构
摘要由一个核心矛盾展开：**轨迹评估应该采用什么证据粒度**。全轨迹验证粒度过粗，难以在长轨迹中聚焦具体失败及其关联证据；原子步骤评分过细，易受噪音干扰且计算成本过高。这一粒度失配进而带来两个挑战。Agent 执行往往存在多条合法有效路径，但粒度失配使评估通常只能提供有限路径参考，因而难以如实衡量多样化 Agent 执行质量。全轨迹评审还会延迟诊断，使无效执行继续浪费资源。
DynSTEER 沿同一逻辑给出三个对应方法：以阶段式动态评估弥合粒度鸿沟，在必要执行节点处划分 rollout 并基于阶段级结果调整多层级评审策略；从公开任务视图编译路径容忍的 Milestone DAG，容纳多样合法路径；终止不可恢复的 Agent 执行，从而控制资源浪费。最后用“Experiments show”式的概括给出区分度和早停节省的核心百分比，不列出具体实验条数。

### 1.3 中英文标准摘要内容

**中文摘要**：
大语言模型智能体越来越多地执行长程任务，引发轨迹评估的核心粒度问题：全轨迹验证粒度过粗，难以在长轨迹中聚焦具体失败及其关联证据；原子步骤评分过细，易受噪音干扰且计算成本过高。这种粒度鸿沟使单参考轨迹范式难以评估 Agent 丰富的合法执行路径，也延迟了长程任务中的及时反馈和早停。为此，我们提出 DynSTEER，一个动态阶段式 Agent 轨迹评估框架。DynSTEER 通过阶段式动态评估弥合粒度鸿沟：在必要执行节点处划分 rollout，并基于阶段级结果调整多层级评审策略；通过从公开任务视图编译路径容忍的里程碑图来容纳多样合法路径并避免参考泄露；并支持终止不可恢复的 Agent 执行，从而控制资源浪费。实验表明，DynSTEER 将评估区分度相较原生评估提升 85.2%，以统计显著性区分全部模型对，并在失败轨迹上节省 45.41% 的执行步骤。

**英文摘要**：
Large language model agents are increasingly deployed for long-horizon task execution, raising a central granularity question for trajectory evaluation: whole-trajectory verification is too coarse-grained to focus on concrete failures and their associated evidence in long trajectories, whereas atomic-step scoring is too fine-grained, noise-sensitive, and computationally expensive. This granularity gap makes a single-reference trajectory paradigm inadequate for assessing the rich space of valid agent execution paths and delays timely feedback and early stopping in long-horizon tasks. To address these issues, we propose DynSTEER, a dynamic stage-wise framework for agent trajectory evaluation. DynSTEER bridges the granularity gap through stage-wise dynamic evaluation that segments rollouts at necessary execution nodes and adapts its multi-tier review strategy from stage-level results; it compiles a path-tolerant milestone graph from public task views to preserve diverse legal paths without reference leakage; and it supports terminating unrecoverable agent executions to curb resource waste. Experiments show that DynSTEER improves evaluation discriminability by 85.2% over native evaluation, separates all model pairs with statistical significance, and saves 45.41% of execution steps on failed rollouts.

**关键词 / Keywords**：`Agent evaluation; trajectory evaluation; milestone graph; adaptive judging; early termination; tool-use agents`

## 2. Introduction

### 2.1 研究背景与关键动因
大语言模型智能体正在逐渐承担越来越复杂和长程的任务执行。任务的长程化使得仅对最终产出结果的评估不足以评判和发现 Agent 的内在不足与失败归因，因此对 Agent 交互轨迹的过程级评估正受到广泛关注。

### 2.2 核心问题：从结果与步骤之间寻找证据粒度
然而，现有轨迹评估范式面临一个核心粒度问题，对长程任务尤为突出。全轨迹验证粒度过粗，难以在长轨迹中聚焦具体失败及其关联证据。原子步骤评分又过细，孤立消息缺乏任务上下文，普通重试和无害观察容易被当作噪音。这种粒度问题进而带来两个挑战。Agent 执行通常存在多条合法且有效的路径。然而，粒度鸿沟使评估往往只能提供有限的路径参考，因而难以如实反映多样化 Agent 执行的质量。此外，全轨迹评审还会延迟本可以更早做出的诊断，使已经执行不佳的轨迹继续运行，浪费模型资源并触发额外的 skill 或工具调用。

### 2.3 DynSTEER 解决方案
为此，本文提出 DynSTEER。首先，它执行阶段式动态评估，在必要执行节点处划分 rollout，使证据既有上下文又不塌缩回整条轨迹，并基于阶段级结果调整多层级评审策略。其次，由于合法任务通常存在多条解法，它通过多候选模拟规划和多数共识从公开任务视图编译路径容忍的里程碑图，而不是匹配单条轨迹。最后，它从阶段级证据中识别不可恢复前缀并终止执行，从而控制资源浪费。

实验概括：实验表明，DynSTEER 将评估区分度相较原生评估提升 85.2%，增强诊断精度，以统计显著性区分全部模型对，保留多样化执行路径的有效性，并在失败轨迹上节省 45.41% 的执行步骤。此段不给出数据集名称或数据规模。

### 2.4 核心贡献点（Contributions）
格式规范：In summary, our contributions are as follows:
- **阶段式动态评估（对应挑战 1）**：在必要执行步骤节点处划分 rollout，并基于阶段级结果调整多层级评审路由，划分上下文充分的局部证据窗口，用于多维评分和首错定位；
- **路径容忍任务蓝图编译（对应挑战 2）**：从公开任务视图经多候选规划和严格多数共识编译里程碑 DAG，在不泄露参考的前提下容纳多样合法路径；
- **反事实早停**：从阶段级证据中识别不可恢复前缀并终止执行，显著减少无效计算。

## 3. Related Works

### 3.1 Agent 轨迹评估（Agent Trajectory Evaluation）
- 现有工作从结果验收推进至轨迹分析（如 BFCL、TRAJECT-Bench、AgentRewardBench、DeepRed、Claw-Eval、AgentProcessBench）；
- 核心局限：(1) 普遍依赖单一人工或合成的标准参考路径比对，对开放有状态环境中的合法多样化替代解法存在严重路径偏置；(2) 事后宏观统计为主，缺乏执行期动态介入与针对性策略调整机制。

### 3.2 Agent 动态评估（Dynamic Evaluation for Agents）
- 静态评测集易面临污染、过拟合与分数饱和，催生动态评测研究（如 ToolSandbox 的交互式里程碑/雷区评测、ATA 的基于 Judge 反馈自适应生成新测例）；
- 核心局限：现有动态评测主要聚焦在测例生成或筛选层面，对单任务内部执行轨迹的动态跟踪仍停留在终态汇合点的简单统计，缺少执行期控制。

### 3.3 高效评估与早停策略（Efficient Evaluation and Early Stopping Strategies）
- 智能体长程运行成本高昂（如 EarlyEval 提出的早期结果预测、基于历史通过率的基准子集精简）；
- 核心局限：基准精简仅减少任务数量未触及单任务内部冗长执行，而黑盒分类器预测缺乏领域语义理解与可信因果归因。

### 3.4 承上启下：DynSTEER 的定位与突破
- 针对上述三大领域空白，DynSTEER 通过公开蓝图编译容纳多路径探索，依托支配锚点阶段提供充分上下文并动态调整评审策略，结合自适应早停切断无效前缀，架起从被动终态验收迈向执行期动态阶段控制的桥梁。

## 4. Methodology

### 4.1 任务形式化与双时钟观测模型（Task Formulation & Dual-Clock Model）
- 权威文献支持：参考 ToolSandbox、InterCode 与 AgentBench 的标准智能体环境建模，将任务形式化为 $T = (x, \mathcal{S}_0, \mathcal{A}, \mathcal{C})$；
- 严格隔离隐藏答案，仅基于公开任务视图 $V_{\text{public}} = (x, \mathcal{A}, \mathcal{I}_0)$ 进行评估；
- 建立双时钟机制：Raw Event Clock（即时安全雷达）与 Closed Action Clock（动作闭合阶段结算）。

### 4.2 路径容忍任务蓝图编译（对应挑战 2）
- 面向 $V_{\text{public}}$ 进行多候选模拟规划推演，生成多样化探索分支；
- 确定性契约与类型校验，剪枝幻觉与死锁环路；
- 严格多数共识聚合与传递约简 $\text{TR}(E)$，提取核心必要里程碑并保留并行替代分支，彻底消除单参考偏置。

### 4.3 具备充分上下文的阶段式对齐（对应挑战 1 基础）
- Ready Frontier $\mathcal{F}_t$ 限制活动候选集，杜绝越级蹭分；
- Lengauer-Tarjan 支配锚点计算：以 $\text{idom}(m^*)$ 划分局部证据窗口 $\mathcal{W}(m^*)$，隔绝并发分支噪音，提供充分上下文并精准定位首错；
- 正确性、效率、安全性、工具规范四维细粒度质量打分。

### 4.4 不确定性自适应评审与执行期早停（对应挑战 1 评审层与挑战 3）
- **核心创新：动态策略自适应调整**。打破传统静态固定标准，根据前序阶段得分与维度不确定性，自适应调整维度权重 $\mathbf{w}_{t+1}$，将高能力 Judge 资源针对性聚焦到智能体的薄弱执行环节；
- **三阶梯 Judge 阶梯路由**：Cheap（规则契约，无模型调用）$\to$ Standard（轻量 LLM）$\to$ Expensive（前沿模型集成，仅在高不确定性与临界薄弱点升级）；
- **执行期自适应早停**：实时拦截致命 Minefield、结构破坏、持续低分与 Frontier 死锁。*(算法伪代码参见附录 Algorithm 1)*

## 5. Experiments

### 5.1 实验设置与评估指标（统一整合至 5.1）
- **评测基准**：ToolSandbox（包含状态快照、动态参数类型与安全雷区不变量，详见附录 A 数据集统计）；
- **被测模型**：DeepSeek-V4-Pro、DeepSeek-V4-Flash、Qwen3-Max、Qwen-Plus，统一采用 ReAct 提示；
- **对比范式**：(1) Native/Default 终态基准验证器；(2) DynSTEER-Replay 阶段式动态评审体系；
- **表 1 停机率口径**：Virtual Policy-Stop Rate 统计 replay 检出的全部 policy stop，包含智能体表现不力与安全雷区两类；它不是真实执行停机率。
- **核心评估指标（统一于此阐明）**：
  - *模型区分度指标（DS）*：依据 Sakai (2006, 2014) 与 Carterette (2012) 的区分力理论，定义 $DS(\epsilon) = (\sigma_{\text{pop}} / \mu) \cdot \sqrt{N_{\text{sig}}(\epsilon) / \binom{M}{2}}$；
  - *蓝图质量指标*：操作级 Micro/Macro F1、致命雷区检出 F1、图编辑距离（GED）拓扑相似度；
  - *效率与早停指标*：对每次 replay 停机运行与同模型、同 repeat、同任务的 Default 完整轨迹配对，把虚拟停机点映射到已记录执行批次，计算停机进度和剩余进度节省率。对每个模型，表 1 的 replay 停机率以该模型评估总体中的 replay 轨迹为分母，表 3 使用同一口径识别出的停机运行总体。Replay 只虚拟截断并记录停机点，不真实重执行被假设省去的后缀。

## 6. Conclusion

本文提出 DynSTEER，将大模型智能体轨迹评估从被动事后终态验收推进到主动的阶段式执行审查。为弥合粒度鸿沟，它在关键执行节点处划分 rollout，并基于阶段级结果调整多层级评审策略；再从公开任务视图编译路径容忍的里程碑图，在不泄露参考的情况下保留多样合法路径；同时支持终止不可恢复执行，以控制资源浪费。实验显示，DynSTEER 将评估区分度提升 85.2%，以统计显著性区分全部模型对，并在失败轨迹上节省 45.41% 执行步骤，为高保真、可诊断、成本可控的智能体评估提供基础。未来工作将研究把阶段级诊断反馈注入 Agent，并在更广泛的长程环境中验证自动恢复闭环。
